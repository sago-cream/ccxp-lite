# ccxpLite 設計指南

ccxpLite 讓資訊密集的校務流程更容易閱讀與操作。優先使用熟悉的原生控制項、清楚的標籤、適度的視覺強調與可預期的導覽。在改善呈現方式的同時，保留原始頁面可正常運作的控制項與送出行為。

本指南整理自 PR #29 的共用 DOM 抽離，以及 #31、#32 的重用經驗。本機套件與 Storybook 描述的是這個儲存庫實際交付的實作。套件採用私有 workspace，與擴充功能一起版本控管，不需要發布到 npm。

## 設計基礎

`packages/tokens/src/index.ts` 是設計變數的唯一來源，匯出基礎值、具語意的 CSS 別名與元件專用值。執行 `bun run design:build` 會產生 `tokens.css` 與擴充功能使用的傳統腳本。請勿手動修改產生的 CSS。`bun run design:check` 會檢查 CSS 是否過期、變數參照是否存在，以及別名是否形成循環。

| 項目     | 規則                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------- |
| 視覺強調 | 操作與導覽沿用柔和的紫色主色；危險色僅用於移除或錯誤。                                                  |
| 表面     | 主要內容使用白色，導覽與次要群組使用低彩度的中性色。以邊框區隔相關內容，避免厚重的容器。                |
| 字體排版 | 使用具語意的字體角色。內文為 16px，輔助文字與說明為 14px。標題建立層級，但不搶走表單操作的注意力。      |
| 語言     | 提供繁體中文與英文標籤，檢查較長的英文文案及中文字換行。                                                |
| 數值資料 | 日期與時間以穩定的欄位對齊。工讀紀錄明確使用 Arial 與等寬數字，因為原先繼承的中文字體無法提供等寬數字。 |
| 間距     | 重用具語意的間距變數。新版面採用 4px 格線；既有的 2／6／10／14px 與視覺微調，需經情境檢視後才更動。     |
| 圓角     | 沿用輸入框、控制項、表面與膠囊形狀的既有角色，不要讓所有元素都採用相同圓角。                            |
| 動態效果 | 回饋應簡短且對應狀態變化。現有操作的轉場為 120ms；資料輸入流程避免裝飾性動畫。                          |

用 `--ccxp-lite-text-muted` 等語意名稱表達用途，並維持既有名稱的相容性。避免新增用途重複的別名，也不要把每個舊版尺寸都提升為通用規則。

## 元件與職責

`@ccxp-lite/ui` 包含 DOM 渲染器、資源控制器、按鈕、圖示、說明浮窗、狀態切換呈現、顯示輔助函式、登入欄位視圖與對話框視圖。建立函式接收所屬的 `Document`，匯入時不依賴 Chrome 或 `CCXP_LITE`。

1. **視圖（View）** 建立擴充功能擁有的 DOM，不搜尋原始頁面，也不送出紀錄。
2. **原始頁面適配器（Host adapter）** 尋找並搬移既有的輸入框、連結、表格與導覽目標，留在 `src/login`、`src/menu` 或對應的功能目錄。
3. **控制器（Controller）** 協調狀態，並透過 `destroy()` 釋放事件監聽器、觀察器及其他資源。

優先重用現有模式。只有操作目的或狀態確實不同時才新增變體；有第二個具體使用情境時，再抽離新的元件。單一頁面特有的版面可使用設計變數與組合指南。

既有的公開命名空間介面仍是相容性契約。`scripts/design-ui-entry.ts` 將元件庫接到這些介面，並把浮窗的清理工作接入應用程式。擴充功能與 Storybook 編譯的是同一份實作原始碼。

## 樣式與舊版頁面

元件類別保留 `ccxp-lite-*` 名稱。共用浮窗 CSS 歸元件庫管理；其他外觀樣式留在各自的介面區域，由本機元件庫的樣式入口匯入，以保留選擇器順序與各區域的變體。

設計變數 CSS 只宣告變數，不包含樣式重設。擴充功能仍將相同變數套用到每一份文件：CSS 變數不會跨 iframe 根節點繼承。建置會將所有資源封裝在本機，並將 workspace 原始碼納入 Firefox 原始碼封存檔。

保留控制項身分、名稱、值、行內事件處理函式與結構樣式。舊頁面的顯示、定位、可見性及溢位設定可能承載行為。樣式清理應留在對應適配器中，不要全面重設原始頁面，也不要移除所有 `!important`。

## 狀態與無障礙

記錄適用的狀態：預設、游標移入、鍵盤焦點、停用、展開、載入中、空白與錯誤。操作使用按鈕，導覽使用連結，輸入框保留可見標籤。純圖示操作需要無障礙名稱，說明內容須支援鍵盤與游標操作。

對話框控制器負責關閉行為、限制鍵盤焦點範圍與還原焦點。顯示預覽不會送出紀錄；批次確認仍是驗證後由功能模組執行的操作。

元件目錄呈現既有行為，並非無障礙認證。紫色與焦點的對比、操作按鈕的明確停用外觀、骨架畫面的減少動態效果，以及舊版移除常用項目控制器的焦點限制，都需要後續改善。變更時須同時檢視元件與原始頁面；這次抽離保留它們既有的行為。

## 審查與驗證

- 一起更新元件、相關範例，以及受影響的指南或組合說明；文件的繁體中文與英文版本也要同步。
- 在 Storybook 檢查中英文、鍵盤焦點、長內容與窄框架。工具列的語言選單可切換文件與範例，預設為 `zh-TW`。
- 執行 `bun run check`、`bun run test:browser`、`bun run build` 與 `bun run storybook:build`。
- 對建置後的目錄執行 `bun run test:design`，驗證瀏覽器呈現與互動。
- 使用 browser-parity 工具比對基準版本與修改後的封裝擴充功能；獨立的預覽無法呈現所有 Kendo、框架組或行內樣式衝突。

抽離作業應維持瀏覽器比對基準。有意的視覺變更需要經審查的前後對照證據，不要只為了掩蓋退步而重新產生快照。
