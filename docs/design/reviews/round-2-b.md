Reviewed 2026-11-04. Scope: Traditional Chinese/English ccxpLite, modernizing NTHU’s university system. Read-only visual assessment against `docs/design/guidelines.md` and a general standard of clear, legible, coherent, usable interface design. No prior or other review was consulted.

## Evidence and limits

I opened every supplied image with `tools.view_image` at original detail, under `.build/design-review/round-2-final/head/`. These are supplied current packaged-extension renders on complete sanitized live-derived legacy DOM with host assets/styles and real embedding. The supplied provenance states that live login was recaptured November 4, 2026, with native live baselines checked for menu/profile/cards/search/dialog. Test names/favorites and an expired anonymous CAPTCHA are documented substitutions. The narrow homepage uses its saved compact rail; the narrow profile/menu screens use menu mode. Those are distinct genuine modes, not an inferred responsive defect.

Accepted supplied measurements: primary/white 5.73:1, danger/white 5.47:1, input boundaries at least 3:1. Supplied packaged checks establish a full-shell native modal and narrow Tab/Shift+Tab focus cycling. I did not rerun those checks. I did not interact with the application or conduct a screen-reader, semantic, zoom, localization, or full accessibility audit. Unshown error/loading/disabled/empty-result states and unobserved behavior are unverified, not presumed broken. The responsive/accessibility scores below cover observed reflow, readability, visible focus, and supplied facts only.

## Screen-by-screen findings

1. **Login — strong.** Standard (`login.png`), wide (`login-wide.png`), narrow (`login-narrow.png`). Clearly labeled fields, readable input values, a dominant purple login action, and distinct secondary actions establish a sensible sequence. Announcement information is separated into its own quiet surface. The wide composition has ample whitespace without stretching form controls. The narrow header wraps into a deliberate two-column link arrangement, the form retains comfortable margins and full-width actions, and announcements move below the task. Deductions are for the slightly uneven form rhythm around the CAPTCHA versus the regular account/password groups, and the modest visual prominence of the help and CAPTCHA utility icons. These are refinements, not demonstrated target-size or accessibility failures. The partial announcement at the panel boundary is mitigated by the visible “顯示全部公告 (13)” action. Do not judge CAPTCHA legibility from the expired documented substitution.

2. **Sidebar — good, information dense.** Classic/empty favorites (`sidebar-classic.png`), populated (`home-favorites.png`), narrow compact rail (`home-favorites-narrow.png`), narrow menu (`sidebar-menu-narrow.png`). Icon alignment, regular row rhythm, category chevrons, tree guides, and filled versus outlined stars make a large legacy function inventory manageable. The empty-favorites instruction is concrete. The visible focus on the sidebar search is clear. The larger deductions concern scanning density when several nested sections are open: repeated small icons, stars, chevrons, and tree guides all compete in the same narrow horizontal band; bilingual names can consume two lines. Compact mode relies on recognizing many similar purple icons, especially the repeated folders, so it is less self-explanatory to newcomers. This is the actual saved compact mode, not a finding that mobile labels were accidentally removed. Tooltip names, accessible names, and hit areas were not inspected. A small density reduction or stronger separation between expanded sections would be optional polish, with care to retain the product’s efficient 36px row standard.

3. **Expanded profile — clear, with a minor state-cue inconsistency.** Desktop (`profile-expanded.png`), narrow (`profile-expanded-narrow.png`), narrow closed (`sidebar-menu-narrow.png`). Preferences, support links, and logout are grouped well, with readable controls and a useful divider above logout. The narrow popover fits within the viewport and preserves readable labels rather than compressing the desktop panel. Its overlay covers content as expected for a menu. The desktop bottom-anchored profile uses an upward chevron when closed and downward when open. The top-anchored narrow profile retains that same pair: the open downward-extending popover shows a downward chevron, while the closed control shows an upward chevron. That makes the visible state cue less natural for the narrow anchor. A mode-aware chevron direction is a minor consistency improvement. This is not evidence that expansion itself is broken. The navigation-mode value pill plus a separate right chevron also adds some visual complexity to an otherwise simple row; simplifying that treatment is subjective polish.

4. **Shared removal dialog — strongest component.** Desktop (`dialog-remove-favorite.png`), narrow (`dialog-remove-favorite-narrow.png`). The backdrop visibly covers the whole shell. The title names the affected favorite, the body explains that removal is reversible, the safe action has initial visible focus, and the destructive action uses a distinct danger color. The narrow modal stays inside the screen, wraps the body naturally, and retains a readable horizontal action pair. Padding and alignment are balanced. The lack of a close icon is not a defect with a visible safe action and supplied keyboard containment. Minor typographic polish: tighten the space before the Chinese question mark in the title, if that is not inherited required host copy. Longer titles, Escape/focus restoration, and assistive-technology announcements remain outside this visual assessment.

5. **Favorite cards — strong.** Desktop (`home-favorites.png`), narrow (`home-favorites-narrow.png`). The icon/title/category/star pattern is easy to repeat and scan. White surfaces and light borders avoid unnecessary weight. The responsive single column preserves readable 16px names, and mixed English/Chinese titles wrap rather than clip. Filled stars consistently express saved status; the recent item’s outline star distinguishes an unsaved item. Deductions reflect the extra vertical density and uneven text rhythm caused by long bilingual names, plus the fact that the star’s effect is communicated mainly by the familiar symbol until the dialog appears. These are small opportunities, not evidence of inaccessible button labels or broken nested interactions. Do not score the narrow menu’s plain navigation rows as if they were homepage cards: they are a different surface.

6. **Homepage search/results — strong, with one concrete copy-state refinement.** Desktop (`home-search.png`), narrow (`home-search-narrow.png`), empty home search (`sidebar-classic.png`). The large search field is easy to discover. Results provide a count, readable names, category context, bold matching terms, and a clearly outlined highlighted row. The purple container and subtle shadow separate the result layer from the page. Narrow results wrap within the panel and visibly preserve a scroll affordance instead of overflowing horizontally. On desktop, however, all six declared results are already visible in full while the footer still says “捲動查看更多結果.” That instruction implies additional hidden results when the shown count and list suggest none. Display it only when the list actually overflows, and preferably hide/update it once the end is reached. The repeated category labels and generous row height slightly reduce scan density; changing those is optional and should preserve comfortable narrow reading. Keyboard selection behavior, announcement of result counts, and empty-query/no-match states were not inspected.

## Remaining work, prioritized

### Concrete corrections worth doing

1. **Make the result-scroll instruction reflect overflow** (`home-search.png` versus `home-search-narrow.png`). The desktop screenshot displays all six results but still invites scrolling for more. This is a minor copy/state accuracy issue, not a task-completion blocker.
2. **Align the narrow profile chevron with its top anchor** (`profile-expanded-narrow.png` versus `sidebar-menu-narrow.png`). The open and closed arrow directions currently follow the bottom-anchored desktop treatment. This is a small state-cue consistency issue, not evidence of failed interaction.

### Subjective polish, not required remediation

- Improve scanning of densely expanded sidebar groups if it can be done without increasing navigation height substantially.
- Refine the CAPTCHA block’s spacing relative to the otherwise regular form rhythm.
- Simplify the navigation-mode value/chevron treatment and tighten Chinese dialog punctuation.
- Consider whether repeated category labels in search deserve less weight; they remain useful context, especially for results spanning categories.

**No release-blocking visual defect is established by these renders.** The main flows appear cohesive and usable at the supplied widths. The remaining verification gaps should not be presented as confirmed accessibility failures, and the good contrast figures and modal checks should not be expanded into a full accessibility-compliance claim.
