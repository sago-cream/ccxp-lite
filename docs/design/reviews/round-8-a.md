## Prioritized refinements

1. **P3 — Separate compact-Sidebar search metadata more clearly.** In both `home-search-narrow.png` languages, “6 results Teaching Feedback” / “6 個結果 教學意見” reads as a single run. Desktop shows a visible middle separator. Retain a visible divider or wrap the category onto its own line when constrained. This affects a saved alternative preference, not the newly shown default phone Menu. Preserve the strong selection outline and readable result type.

2. **P3 — Consider a little more separation between the narrow login utility links if it can be done without harming targets or reintroducing excessive header height.** `login-narrow.png` packs four purple links into one row with external-link marks doing much of the separation work. It is readable at the shown width, so this is a polish opportunity rather than a reason to revert the compact arrangement. Do not claim English utility-header coverage from this Chinese screenshot.

3. **P3 / optional — Strengthen profile-panel attachment only if real use shows ambiguity.** The narrow popover is positioned close to the avatar and has an expanded chevron, which is adequate. A subtle surface continuity/anchor cue could make ownership still clearer. Avoid adding explanatory labels or changing the already clear preference/support/logout grouping.

The dense nested desktop sidebar is a tradeoff rather than a demonstrated failure. Keeping the existing tree guides and independently aligned star/chevron columns is preferable to truncating long host titles. The compact phone rail also remains a reasonable explicit preference; its width cost should not be scored as though it were the new default.
