## Prioritized feedback

1. **P2 — Prefer the labeled full-width Menu for first-time narrow use, while respecting an explicit sidebar preference.** In `home-favorites-narrow.png` and `home-search-narrow.png`, the approximately 64px rail takes about one sixth of a 375px viewport. “Tentative schedule” and “Course evaluation” wrap to additional lines; category actions show icons without visible labels. In `sidebar-menu-narrow.png`, the same long favorite label has substantially more room and categories have names. The existing Menu already supplies a practical implementation path. This is a discoverability and reading-efficiency improvement, not evidence of broken navigation.

2. **P2 — Make narrow search metadata separation explicit.** Desktop `home-search.png` shows a clear separator between the result count and category. Both narrow language captures read as a single phrase (“6 個結果 教學意見” / “6 results Teaching Feedback”). Preserve a visible separator with spacing or place the category on its own line when space is tight. Keep the current result font size and strong active-state outline.

3. **P3 — Give the homepage favorite disclosure a clear scope/count near its section.** Desktop `home-favorites.png` shows eight cards and a small trailing “顯示全部 →”; the narrow/full Menu explicitly says all favorites (10). Surface the total in the homepage section/disclosure and keep that affordance visually tied to the group, using existing tokens/UI patterns. The supplied ordering/disclosure checks already establish behavior; this suggestion addresses preview comprehension.

4. **P3 — Consider a modest popover attachment cue.** The profile panel is clean, but in narrow captures it begins below the avatar and covers content as a free-standing rectangle. A small anchor treatment or clearer avatar-expanded surface continuity would help users understand its owner without adding explanatory copy. Keep the present grouping and economical labels.

5. **P3 — Reduce optional-link header height on narrow login if mobile task speed is a priority.** The four institutional links occupy two extra rows before the login heading, while the announcement panel begins near the bottom of the viewport. Keep all links available, but consider a more compact arrangement. The current form remains comfortably usable; this is a polish opportunity.
